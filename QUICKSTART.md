# Sentinel X — Quick Start Guide

## Prerequisites
- Kali Linux (or any Debian/Ubuntu-based system)
- Root / sudo access
- Internet connection for package installation

---

## Step 1 — Extract the zip

```bash
unzip sentinelx-v5.zip
cd sentinelx
```

---

## Step 2 — Run the setup script

```bash
sudo bash setup.sh
```

This will:
- Install `nmap`, `postgresql`, `nodejs`, `npm`
- **Create your `.env` file** with auto-generated secrets
- Install all Node.js packages (`npm install`)
- Create the PostgreSQL user + database
- Run all database migrations
- Optionally install as a systemd service

---

## Step 3 — Start the server

```bash
npm start
```

Open your browser: **http://127.0.0.1:3000**

Default credentials: `admin` / `SentinelX@admin`

---

## If You Get Database Errors

### Option A — Re-run the DB setup script alone

```bash
sudo bash scripts/db-setup.sh
```

### Option B — Manual PostgreSQL setup

```bash
# Start PostgreSQL
sudo systemctl start postgresql

# Create user and database
sudo -u postgres psql -c "CREATE USER sentinelx WITH PASSWORD 'sentinelx';"
sudo -u postgres psql -c "CREATE DATABASE sentinelx OWNER sentinelx;"
sudo -u postgres psql -c "GRANT ALL PRIVILEGES ON DATABASE sentinelx TO sentinelx;"

# Run migrations
node src/db/migrate.js
```

### Option C — Fix pg_hba.conf (most common issue on Kali)

If you see `password authentication failed` or `peer authentication failed`:

```bash
# Find and edit pg_hba.conf
sudo nano /etc/postgresql/*/main/pg_hba.conf
```

Find this line:
```
local   all             all                                     peer
```

Change to:
```
local   all             all                                     md5
```

Also ensure this line exists:
```
host    all             all             127.0.0.1/32            md5
```

Then restart:
```bash
sudo systemctl restart postgresql
node src/db/migrate.js
npm start
```

## Running Without a Database

The server starts fine without PostgreSQL. It runs in **memory-only mode** — all scan results, hashes, and sessions are stored in RAM and lost on restart.

To verify: `curl http://127.0.0.1:3000/health`

## .env File

Your `.env` is auto-generated by `setup.sh`. Key variables:

| Variable | What it is |
|---|---|
| `API_KEY` | Required in `X-API-Key` header for all API calls |
| `JWT_SECRET` | Signs JWT tokens — keep secret |
| `DB_*` | PostgreSQL connection details |
| `NMAP_BINARY` | Path to nmap (auto-detected) |
| `ANTHROPIC_API_KEY` | For AI Analyst (optional) |

To regenerate `.env` from scratch:
```bash
cp .env.example .env
# Then edit with your values
nano .env
```

## npm Scripts

```bash
npm start          # Start production server
npm run dev        # Start with nodemon (auto-restart on file changes)
npm run db:migrate # Run DB migrations manually
node src/test.js   # Run API test suite (server must be running)
```

---

## Verify Everything Works

```bash
# Health check (no auth needed)
curl http://127.0.0.1:3000/health

# NMAP status (replace YOUR_API_KEY with value from .env)
curl -H "X-API-Key: YOUR_API_KEY" http://127.0.0.1:3000/api/nmap/status

# Login
curl -X POST http://127.0.0.1:3000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"SentinelX@admin"}'
```

## Directory Structure

```
sentinelx/
├── .env                  ← Your config (auto-generated by setup.sh)
├── .env.example          ← Template — copy to .env if missing
├── setup.sh              ← Full setup script (run as root)
├── scripts/
│   └── db-setup.sh       ← DB-only setup (if main setup fails)
├── src/
│   ├── server.js         ← Express + WebSocket entry point
│   ├── db/               ← PostgreSQL pool, migrations, repository
│   ├── modules/          ← NMAP engine, hash cracker, AI analyst
│   ├── routes/           ← REST API endpoints
│   ├── middleware/        ← Auth, rate limiting, error handling
│   └── utils/            ← Logger, MD4
├── public/               ← Frontend dashboard
│   ├── index.html
│   └── js/
│       ├── api.js        ← Backend API client
│       ├── ws.js         ← WebSocket client
│       ├── app.js        ← App controller & navigation
│       ├── modules.js    ← NMAP / Hash / Wordlist / AI sections
│       └── ui.js         ← Toast, modal, formatters
├── reports/              ← Scan output files
├── logs/                 ← Application logs
└── wordlists/            ← Custom generated wordlists
```
